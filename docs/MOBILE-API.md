# CasePingo mobile API (v1)

Used by the Expo app in `mobile/` (Step 9B). Personal cases only; law-firm features stay on the website. No purchasing in the app: it shows the plan, and upgrades happen on casepingo.com.

**Sign-in:** the app signs in with Supabase Auth directly and sends `Authorization: Bearer <access token>` on every request. Requests that change data accept only the token, never the website's cookies. Two-factor users need a token from after their code (aal2). Responses are JSON with `cache-control: no-store`; errors look like `{"error": "code", "message": "Readable text", "field"?: "receipt"}`.

| Method | Path | What it does |
|---|---|---|
| GET | `/api/v1/config` | Consent wording and version, receipt hint (no sign-in needed) |
| GET | `/api/v1/assistant` | **Switched off for now: answers 404** (`FEATURES.assistant`). When on, the assistant for this account: `{available, plan, limit, used, remaining}` (questions per UTC day; `available` is false until the server has `ANTHROPIC_API_KEY`) |
| POST | `/api/v1/assistant` | **Switched off for now: answers 404.** When on, ask: `{messages: [{role: "user"|"assistant", content}], caseId?}` (recent turns, ending with the question; nothing is stored). Errors before the answer are JSON with `error`: `unavailable` (503), `invalid`/`too_long` (400), `limit` (429, with `plan` and `limit`). Otherwise the answer streams as newline-delimited JSON (`application/x-ndjson`): `{"type":"text","text"}` pieces, `{"type":"reset"}` (discard the text so far), `{"type":"refusal"}`, `{"type":"error","error":"busy"|"failed","message"}`, and finally `{"type":"done","remaining","stop"}`. With `caseId` (the person's own case), the assistant also gets that case's form and status, never the receipt number |
| GET | `/api/v1/civics` | Civics test practice: `{defaultVersion, currentAsOf, practicePassShare, text, links, versions: [{version: "2025"|"2008", title, who, format, listUrl, total, rules: {standard, senior: {ask, pass, failAt}}, sections, questions: [{id, n, section, q, answers, note?, star, kind: "fixed"|"current"|"local", pick, right?, wrong?}]}]}`. Questions and answers are USCIS's official lists; `right`/`wrong` are practice choices (none for `local` questions); `senior` is the 65/20 format (no sign-in needed) |
| GET | `/api/v1/resources` | The resource center for the Resources tab: `{statusLibrary, resources: [{slug, title, summary, intro, sections, faq?, links}], tools, contactEmail}` in English and Spanish; `tools` are official government tools (`[{key, icon: {ios, md}, title, summary, url}]`: e-Request, processing times, I-94, fee calculator, change of address) that open on uscis.gov or cbp.dhs.gov; links are official pages or website paths (`/status-guide`, `/visa-bulletin`, `/civics-test`, `/resources/…`) the app maps to its own screens; `contactEmail` is `null` until `NEXT_PUBLIC_CONTACT_EMAIL` is set (no sign-in needed) |
| GET | `/api/v1/guide` | The status guide for the app's Status guide tab: `{stageCount, entries: [{slug, heading, wordings, category, stage, path, en, es}]}` (no sign-in needed) |
| GET | `/api/v1/me` | Profile, plan, case counts, alert settings |
| PATCH | `/api/v1/me` | `{name?, locale?: "en"\|"es", emailOnChange?, pushOnChange?}` |
| DELETE | `/api/v1/me` | `{"confirm": "DELETE"}`: deletes the account (cancels billing first). 409 `firm_owner` if they own a firm |
| GET | `/api/v1/cases` | The person's cases (masked receipts only), each with `category`, `stage`, `form`, `recentApprovalAt`, `lineMap`, `days` and `tags` (`[{id, name, color}]`, A to Z); plus `stageCount` |
| POST | `/api/v1/cases` | `{receipt, nickname?, basis: "SELF"\|"AUTHORIZED_BY_APPLICANT", consent: true, statementVersion}` → 201 `{caseId, check}`. 400 `invalid_receipt`, 409 `duplicate` / `consent_outdated`, 403 `plan_limit` |
| GET | `/api/v1/cases/:id` | Status, plain-language guide, form and office, our observed changes, USCIS history, consent, congratulations, `tags`, `lineMap`, `days` |
| PATCH | `/api/v1/cases/:id` | `{nickname: string \| null}` (up to 60 characters): rename the case or clear the nickname |
| DELETE | `/api/v1/cases/:id` | Remove the case and stop checks |
| POST | `/api/v1/cases/:id/refresh` | Refresh now → `{status: "updated", changed, message}`. 429 `cooldown` / `limit` / `budget`, 409 `paused` / `no_consent`, 502 `failed` |
| POST | `/api/v1/cases/:id/check-instead` | Free plan: check this paused case instead |
| PUT | `/api/v1/cases/:id/tags` | `{tagIds: string[]}`: exactly these tags on the case (up to 10) → `{tags}`. 404 for a case or tag that isn't the person's, 403 `limit` |
| GET | `/api/v1/tags` | The person's tags, A to Z: `{tags: [{id, name, color, caseCount}], colors, limits: {perPerson, perCase, name}}` |
| POST | `/api/v1/tags` | `{name, color?}` (1 to 24 characters; color one of `blue`, `green`, `amber`, `red`, `purple`, `gray`, picked when left out) → 201 `{tag}`. 400 `invalid`, 409 `duplicate` (same name, any capitals), 403 `limit` (20 tags) |
| PATCH | `/api/v1/tags/:id` | `{name?, color?}`: rename or recolor → `{tag}` |
| DELETE | `/api/v1/tags/:id` | Delete the tag; it comes off every case (the cases stay) |
| GET | `/api/v1/cases/:id/insights` | Case analysis: how this case compares with others like it, from personal cases tracked in CasePingo, combined anonymously. `{insights: {form, mode, minGroup, similarWindowDays, poolSize, dataAsOf, monthly: {month, lastMonth, today, daysInMonth, thisMonth: number[], last: number[], thisTotal, lastTotal}, yourCase: {filed, days, finished, daysAtStatus, lastUpdate, office, status}, guideNext, next: {cases, options: [{title, share, cases, medianDays, avgDays}]}, similar: {cases, steps: [{key, label, cases, you}], aheadOf, approvedShare, rank, of}, offices: {overallMedianDays, cases, rows: [{code, name, medianDays, cases, yours}]}, rates: {approval: {rate, decided}, rfe: {rate, cases}}, activity: [{window: "day"\|"month"\|"year", from, cases, kinds: [{key: "card"\|"approved"\|"processing"\|"interview"\|"evidence"\|"denied"\|"other", label, cases, share}]}], trend: {months: [{month, approved, evidence, denied}], total}, processingTimesUrl}}`. `monthly` adds approvals up day by day (this month so far against last month); `similar.rank` is this case's place among cases filed within 30 days (1 = furthest along) out of `of`; `activity` shares have one decimal. A section is `null` (or `cases: null`) until at least `minGroup` (10) different cases are behind it. Counts each receipt once, never includes law-firm cases, and uses only statuses from the USCIS connection the server runs on (`mode`; anything but `production` is demo data). Comparisons leave out the person's own cases. No receipt numbers, names or nicknames in the answer. 404 for a case that isn't the person's |
| GET | `/api/v1/updates` | The Updates tab: the person's status changes across all cases, newest first (up to 60): `{updates: [{id, caseId, nickname, receiptMasked, form, statusTitleEn, statusTitleEs, category, at, reportedDate, first}]}`. `at` is when CasePingo saw the change; `reportedDate` is USCIS's date (`YYYY-MM-DD`) when known; `first` marks the status CasePingo saw when tracking started. Read/unread is kept on the phone |
| GET | `/api/v1/journey` | My timeline: every case on one chart. `{start, end, totalDays, cases: [{id, nickname, receiptMasked, form, office, statusTitleEn, statusTitleEs, start, end, days, finished, tone}], milestones: [{date, day, caseId, form, titleEn, titleEs, category}]}`. Days count from the earliest filing to the latest end (the last update for a finished case, today otherwise); `day` is the milestone's day number from `start`. All `null`/empty until USCIS reports dates |
| POST | `/api/v1/devices` | `{token: "ExponentPushToken[…]", platform: "ios"\|"android", appVersion?}`: turns push alerts on |
| DELETE | `/api/v1/devices` | `{token}`: stop pushes to this phone (sign-out) |

**Case fields added for the status guide and the approval moment:**

| Field | Where | Meaning |
|---|---|---|
| `category` | list, detail, each `events[]` and `uscisHistory[]` item | `"progress"`, `"action"`, `"done"` (approved), `"stop"` (decision) or `"none"`; drives the coloured pill and timeline dot |
| `recentApprovalAt` | list | When CasePingo saw the case become approved, if within the last 30 days; else `null` |
| `stage` | list, detail | Step on the progress line, 0–3: Received, In review, Decision, After the decision (`null` before the first check). Side statuses such as a transfer count as In review |
| `form` | list, detail | `{code: "I-485", name: {en, es} \| null}` or `null` |
| `guide` | detail | `{slug, path, en, es}`, each language `{meaning, next, todo}` (todo may be `null`); `null` when the status isn't in the guide. Open `path` on the website for the full page |
| `office` | detail | Office that received the case, from the receipt prefix: `{code: "LIN", name: {en, es} \| null}` |
| `processingTimesUrl` | detail | USCIS's official processing-times page (USCIS offers no API for it) |
| `lineMap` | list, detail | The case's steps for its kind of case: `{scenario, name: {en, es}, steps: [{key, label: {en, es}, state: "done"\|"current"\|"upcoming", date: "YYYY-MM-DD" \| null}], current, tone: "progress"\|"action"\|"done"\|"stop", marker: {en, es} \| null, outcome, finished}`. Scenarios: green card (I-485), work permit (I-765), card renewal (I-90), removing conditions (I-751, I-829), citizenship (N-400), travel document (I-131), asylum (I-589), family petition (I-130), fiancé(e) (I-129F), asylee relative (I-730), petition (I-140, I-129, I-360, I-526E), and a general one for other forms. `marker` is the short label over the current step ("Evidence requested", "Interview scheduled"); `current` is `-1` before the first check. Side statuses (a transfer, updated details) keep the furthest step reached |
| `days` | list, detail | `{filed, lastUpdate, total, sinceUpdate}`: dates as `YYYY-MM-DD`, `total` days from filing to the last update (finished) or today, `sinceUpdate` days since USCIS's last update; `null` when unknown |
| `celebration` | detail | `{approvedAt, nextStep: {en, es} \| null}` while the approval is recent; the app shows the congratulations card and plays the star burst once per phone |

Only approvals CasePingo watched happen count (an approved status after an earlier one), so adding a case that was already approved doesn't trigger the celebration. The guide text comes from the server, so its wording can improve without an app release.

**Push alerts:** when a personal case's status changes, the owner's active phones get a push through Expo's push service (title "Case update", body "label: status", data `{caseId}`), in their language, with the masked receipt only. Each (status change, person) is pushed once. Tokens Expo reports as dead are switched off.
